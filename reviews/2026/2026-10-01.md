## devlog

### 🟠 medium — Temp directory leaked on every `agy` call when `cwd` is not provided

`src/ai.js:20` · commit `1d7af32`

`mkdtempSync(join(tmpdir(), 'ai-'))` creates a new temporary directory on each invocation and never deletes it. For a nightly script this is low-frequency, but the directory is created unconditionally whenever `cwd` is `undefined` and `agy` exists — including on every transient failure that falls through to the `claude` fallback — so it silently accumulates across runs.

**Fix:** pass `tmpdir()` directly as a stable working directory (or a single named subdir like `join(tmpdir(), 'agy-devlog')`) instead of creating a fresh temp dir each call, or clean up with `rmSync` in a `finally` block.

### 🟡 low — `agy` result silently swallowed on non-SUCCESS status with non-empty response

`src/ai.js:22–23` · commit `1d7af32`

## dispecink

### 🔴 high — `parse_iso_ms` panics on malformed date from `agy /usage`
`src-tauri/src/usage.rs:188,196` · commit `633db87`

`d[0]`, `d[1]`, `d[2]` and `t[0]`, `t[1]` are direct Vec index operations with no length guard. If `agy /usage` ever returns a line whose reset timestamp has fewer than 3 date components or fewer than 2 time components (e.g. on a parse error, a locale change, or a future format tweak), Dispečink crashes with an index-out-of-bounds panic instead of gracefully returning `None`. The `?` operator is used when building the Vec but cannot catch this indexing.

**Fix:** replace bare index operations with `.get()` calls and `?` — e.g. `let (y, m, day) = (d.get(0).copied()?, d.get(1).copied()?, d.get(2).copied()?);` and likewise for `t[0]`, `t[1]`.

### 🟠 medium — `forward()` advances `since` before async calls finish, silently dropping agent replies
`src/phone.ts:98-99` · commit `6d873d9`

`since = new Date().toISOString()` is set on line 99, before any `await pc(...)` call has returned. If the Paperclip API is slow and the 60-second interval fires a second invocation (no `busy` guard here, unlike the relay's `push`), the second run also snapshots `since` at the current time. Any agent comments that arrived between the first run's start and the actual completion of its fetches — exactly the window where comments most likely land — are silently skipped and never forwarded to Telegram.

**Fix:** add a `busy` flag mirroring the relay's `push`, or move `since = new Date().toISOString()` to after all awaits have completed (capture `const nextSince = new Date().toISOString()` before the loop, set `since = nextSince` only if no error was thrown).

### 🟡 low — Unauthenticated local HTTP server accepts permission decisions from any local process
`src-tauri/src/claudecode.rs:199-215` · commit `3f4fffe`

`tiny_http::Server::http("127.0.0.1", 47811)` listens with no token, no path secret, and no origin check. Any process running as the same user (a malicious script, a compromised shell command, another app) can POST to `/cc/permission` with `{"hook_event_name":"PermissionRequest","tool_use_id":"…"}` to inject or deny Claude's permission decisions silently. ### 🔴 high — `apply()` deletes the plan file even if `shutil.move` partially fails mid-loop

`uklid.py:104` · commit `c147cd9`

`os.remove(PLAN)` runs unconditionally after the loop, even when some items failed. If `shutil.move` raises mid-loop (e.g. permission error, cross-device move), the plan is still deleted, meaning the failed items are silently lost — the user is never offered a retry and those paths won't appear in the next scan until the weekly cron re-discovers them. ### 🟠 medium — State is written even when a network error occurs for every route

`letenky.py:53` · commit `a31345c`

`json.dump(state, open(STATE, "w"))` runs unconditionally at the end of `main()`. If every route raises (network down, Ryanair API changed), all prices in `state` are overwritten with whatever was accumulated — in this case nothing new — but the file is still rewritten. More critically, if the script is interrupted after a partial run, a route that fired a notification has its new (lower) price saved, but a route that errored is left at its old threshold; the next successful run will not re-notify because `state.get(key)` still holds the old lower price. This isn't catastrophic today (one route) but will silently suppress alerts when more routes are added. Fix: only persist `state` when at least one route was checked successfully, or track per-route `last_checked` separately from `last_notified_price`.

### 🟠 medium — truncation of an oversized part leaves the `<blockquote>` tag unclosed before it is re-closed

[`server/scout/telegram.ts:57`](file:///Users/erickos007/Developer/job-tracker/server/scout/telegram.ts#L57) · commit `6c3085b`

`p.slice(0, LIMIT - 60)` slices raw HTML bytes that were already produced by `fold()`, which wraps the content in `<blockquote expandable>…</blockquote>`. The slice can cut in the middle of an HTML entity (e.g. `&amp;`) or — more importantly — will land somewhere inside the already-escaped body content, not right before the closing tag; the hardcoded `</blockquote>` appended afterward then creates a double closing tag because the one inside `fold()` is still present if the slice happens past it, or leaves the block unclosed if the slice lands before it. Fix: truncate `body` *before* passing it to `fold()`, not after, so the wrapper tags are always intact.
