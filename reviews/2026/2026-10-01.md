## devlog

### 🟠 medium — `scratch()` dir is shared across concurrent `agy` calls, causing potential cwd contamination

`src/ai.js:8–11` · commit `eec466e`

`scratch()` always returns the same path (`/tmp/ai-agy`) and never cleans it up between calls. If `agy` writes files to its cwd (e.g. conversation state, temp artifacts), a second concurrent invocation — or the next night's run — operates in a directory that may contain stale files from a previous run, potentially affecting `agy`'s behaviour or leaking data between sessions. The old `mkdtempSync` was isolated-per-call for exactly this reason.

**Fix:** either clean the dir at the start of each call (`rmSync(dir, { recursive: true, force: true })` before `mkdirSync`) or use `mkdtempSync` as before but delete the dir in a `finally` block after `spawnSync` returns.

### 🟠 medium — `raw.slice(raw.indexOf('{'))` silently misparsed when output contains no `{`

`src/ai.js:25–26` · commit `eec466e`

When `agy` exits with a non-JSON error message (no `{` in stdout), `raw.indexOf('{')` returns `-1`, so `raw.slice(-1)` yields the last character of the string — a one-character string that `JSON.parse` will throw on. The `catch` block swallows this and falls through to `claude`, which is safe, but the guard `r.stdout ?? ''` was meant to fix null crashes yet the `-1`/`slice(-1)` path was already present in the old code and remains unaddressed.

**Fix:** add a guard before parsing: `if (!raw.includes('{')) throw new Error('no JSON');` — or use `raw.indexOf('{')` with an early-exit: `const i = raw.indexOf('{'); if (i === -1) throw …`.

`src/review-tasks.js:50–52` · commit `d00f1e3`

If the `GET /companies` response does not contain a company named `'Nexus Grind Ops'` (e.g. a rename, a first-run against an empty instance, or an API change), `company` is `undefined`. ## dispecink

### 🟠 medium — Hook secret falls back to all-zero key if `/dev/urandom` open fails
`src-tauri/src/claudecode.rs:60` · commit `576893c`

`bytes` is initialized to `[0u8; 24]` and only filled if `File::open("/dev/urandom")` succeeds; if it fails (unlikely on macOS, but possible in a sandbox), `read_exact` is skipped silently and the key becomes the fixed string `"000000…"` (48 hex zeros), which passes the `>= 32` length check on next launch and is never regenerated. Every install where this path triggered would share the same effectively public secret, breaking the auth entirely. Replace the `if let Ok` with an early-return error or use `getrandom`/`rand` so a generation failure is surfaced rather than silently accepted.

### 🟠 medium — Hook secret is baked into Claude Code's `settings.json` as a plain query parameter
`src-tauri/src/claudecode.rs:336` · commit `576893c`

`hook()` writes the literal secret into the `curl` command string that lands in `~/.claude/settings.json` and is replayed verbatim by Claude Code on every hook event — including `PreToolUse`, which Claude logs in its session transcripts (`~/.claude/projects/…/logs/`). Anyone who can read those logs (or the settings file) gets the key. A better pattern is to read the key from a file at hook execution time (e.g. `$(cat ~/Library/Application\ Support/cz.erikkarasek.dispecink/cc-hook-key)`) so the raw secret never appears in the settings or transcripts.

### 🟠 medium — Phone-triggered PR merge/close carries no ownership check
`src/relay.ts:113` · commit `3bb7180`

The relay delivers any `{"kind":"pr","action":"merge","repo":"…","number":…}` command straight to `github_pr_action` without verifying that `cmd.repo` is in the user's configured `cfg.githubRepos` list. ### 🟡 low — `pull_requests` discovery adds repos not validated against the configured list
`src-tauri/src/github.rs:136` · commit `3dca387`

`gh search prs --owner <owner>` can return repos that the user never added to `cfg.githubRepos`. These are appended to `all` and passed through `is_repo()` (which only validates the `owner/name` format, not membership in any allowlist), then fetched and serialised into the relay state. ## gemini-jobs

### 🔴 high — Fallback writes raw model output (potentially huge) to the report untruncated, then POSTs it all to Paperclip

`run.sh:23` · commit `ee185c2`

The new `else` branch concatenates the *entire* raw `lines` list (which can be megabytes of narrated tool calls) into the report and then that full file is read and posted as the `description` field to the Paperclip API. If the model timed out mid-stream or crashed with verbose output, the POST body could be arbitrarily large, likely exceeding any API payload limit and silently failing — or, worse, succeeding and creating a bloated, unparseable issue card. **Fix:** cap the fallback to a reasonable slice, e.g. `lines[:100]` (or the last 100 lines), before writing.

### 🟠 medium — `$report.tmp` is not cleaned up on failure because `set -e` exits early

`run.sh:7,15` · commit `ee185c2`

`set -euo pipefail` causes the script to abort on any error (e.g., `agy` or the Python snippet failing), but `rm -f "$report.tmp"` is only reached when execution completes normally — there is no `trap`. Stale `.tmp` files accumulate and will be picked up as stale inputs on the next run if a filename collision occurs. **Fix:** add `trap 'rm -f "$report.tmp"' EXIT` immediately after the `report=` assignment.

### 🟡 low — Hardcoded `projectId` and company UUID in production script

`run.sh:47,50` · commit `ee185c2`

The Paperclip `projectId` (`fde92fc1-…`) and company ID (`64a29749-…`) are baked into the script. If this repo is ever made public or shared, those IDs leak; they also make the script brittle to any Paperclip migration. **Fix:** move both values to environment variables (e.g., `PAPERCLIP_PROJECT_ID`, `PAPERCLIP_COMPANY_ID`) read at runtime.

### 🔴 high — `parseModelArray` second `JSON.parse` is unguarded and can crash callers

`src/lib.js:103` · commit `aaded8e`

The fallback `JSON.parse(raw.replace(…))` inside the `catch` block has no try/catch of its own. Any model output that fails to parse for a reason *other* than the Czech-quote pattern (e.g. a stray control character, truncated response, or a `\u` escape) throws a `SyntaxError` that propagates straight through `pick()` in `digest.js` / `index.js`, crashing the whole nightly run and silencing the morning digest.

**Fix:** wrap the second `JSON.parse` in its own try/catch and return `[]` (or re-throw with a descriptive message) on failure, the same way the first failed parse already falls through gracefully.

## job-tracker

### 🔴 high — Shrinking loop can produce a chunk that still exceeds `LIMIT`, crashing the send

`server/scout/telegram.ts:50` · commit `b95c6b0`

The `while` loop shrinks `b` until `html.length > LIMIT - 60` is false **or** `b.length === 0`. When `b` reaches zero length the loop exits, but `wrap('')` still produces the fixed template (`<b>title</b>\n<blockquote expandable>…</blockquote>`) whose own markup is ~50–60 characters — so `html` may still be longer than `LIMIT - 60` if the title is long, and it is returned as-is. That `part` is then accumulated into `chunk` without any further length guard, so a single over-limit chunk can be passed to `send()`, which will receive a 400 from Telegram's 4096-character API limit. **Fix:** add a hard guard after the loop — e.g. `if (html.length > LIMIT) return ''` (or throw) — or seed the `while` condition with a minimum `b.length > 0` check that is already there but pair it with a post-loop assertion.

### 🟠 medium — `AND a.stage = f.kind` silently drops `interview`-kind nudges when the card moves to `offer`

`server/followup/followup.ts:87` · commit `4b978ad`

The `kind` column only ever holds `'applied'` or `'interview'` (see line 13 and the INSERT at line 70), while `a.stage` advances further — e.g. to `'offer'` or `'rejected'` — after the follow-up is written. An interview-stage nudge that was drafted before the recruiter replied will be silently filtered out the moment the card moves to `'offer'`, meaning the user never sends a follow-up that is still useful ("I got your reply, excited about the offer…"). The intent was only to suppress nudges for cards that have moved *backwards or sideways*; a forward stage-move should not suppress an `'interview'` nudge. **Fix:** instead of exact equality, check that the card's stage has not *regressed*: e.g. `AND a.stage NOT IN ('rejected', 'ghosted', 'closed')`, or store the intended target stage explicitly in the `followups` row.
