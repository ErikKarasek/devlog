### 🟡 Low — Memoised severity is wrong for packages in a dependency cycle
`src/deps.js:52-63` · commit `764229c`
`severity()` stores a result in `memo` even when it was cut short because `seen` blocked a back-edge in a cycle. Cycles do occur in `npm audit` `via` chains. A package reached through the cycle can then be cached without the severity of the package that started it, so the count and top list depend on iteration order and can be too low. There is no test for this new logic. To fix it, don't write to `memo` when the traversal hit a `seen` node, or compute severities over strongly connected components. Then add a small fixture-based test with a cycle and with an ignored advisory.
