## devlog

### 🟠 medium — Catch-up marks a day as done even when the AI summary failed
`src/index.js:142` · commit `4f71d9b`
When `claude()` fails, the entry is written with the "AI summary unavailable" placeholder. Line 268 then advances `lastDay` regardless, so the day is never retried. A 3:00 wake-from-sleep run is exactly when the network may still be down. `telegram()` (line 201) has no try/catch either, so a network error throws mid-loop. Days already written in that run then never reach `publish()`, because their state was advanced but they were never committed. Fix: only advance `lastDay` when the summary succeeded, and wrap the Telegram call in try/catch so a send failure doesn't abort the loop.

### 🟠 medium — Secret redaction runs after truncation, so partial secrets can leak
`src/chats.js:61` · commit `0cc9655`
Prompts are cut to 300 characters and the assistant reply to 1500 (line 73) before `redact()` runs. A token straddling the cut is reduced to a prefix. That prefix is shorter than the regex minimums (30, 20 or 40 characters), so it passes through unredacted. The text then goes into the log that is pushed to GitHub. Fix: call `redact()` on the full text first, then truncate.

### 🟠 medium — Heartbeat and state hide review failures
`src/review.js:98` · commit `60346a4`
A failed review only returns a "⚠️ Review failed" section. `review.js` still exits 0, so `daily.sh` sends the site-watch beat, and line 156 advances `lastRun`. Those commits are never reviewed again, and the watchdog reports that everything is fine. Fix: don't advance the state, and exit non-zero, when any repo's review failed.

### 🟠 medium — Dependency report shows "✅ no known issues" when the audit failed
`src/deps.js:54` · commit `07ab3d3`
`json()` returns `null` on offline or error, and `counts` then falls back to `{}`. The repo is reported as "✅ bez známých chyb" (no known issues), which is false reassurance. Fix: if `audit` is `null`, report "audit failed" for that repo instead.

### 🟡 low — `.env` quotes are not stripped in `deps.js` and `daily.sh`
`src/deps.js:19`, `scripts/daily.sh` (`beat()`) · commits `07ab3d3`, `60346a4`
`index.js` and `review.js` strip surrounding quotes from `.env` values, but `deps.js` and the shell `BEAT_KEY` extraction don't. If a value is quoted, the Telegram request or the beat key is wrong, so the report or heartbeat silently fails. Fix: strip quotes the same way in both places.

### 🟡 low — One malformed `package.json` aborts the whole dependency report
`src/deps.js:49` · commit `07ab3d3`
The unguarded `JSON.parse` in `check()` throws for a single bad repo, so no report is sent for any repo. Fix: wrap each `check(name)` call in try/catch and skip or flag that repo.

## job-mail

### 🟠 medium — Weekly summary failure fails the whole digest run and skews the beat
`src/digest.js:155` · commit `0829406`
`weekly()` runs at top level after the daily message is already sent. If it throws (a corrupt line in `replies.jsonl` breaks `JSON.parse`, or `/api/stats/period` returns an error), `node` exits non-zero. `digest.sh` then shows "digest failed" and skips the site-watch beat, even though the daily digest went out. Wrap the weekly block, and the `JSON.parse` per line, in try/catch, and log the error without changing the exit code.

### 🟠 medium — `replies.jsonl` gets duplicate rows, which inflate the weekly counts
`src/index.js:196-205` · commit `0829406`
- The README tells you to backfill with `--log-only --days 14`. That appends every reply again, including ones the normal run already logged, so "Odeslané", "Pozvánky" and the other reply counts double.
- `logReply` also runs for `--fixture` runs that aren't `--dry`, so test mails end up in real stats.
- If `telegram()` throws mid-loop, state isn't saved, so the next run re-sends and re-logs the same mails.

Dedupe on `at` plus `company` plus `category` (or the mail uid) when appending, and skip logging for fixtures.

### 🟡 low — `/prehled` on a Monday also sends the weekly summary
`src/bot.js:157` · commit `8a1c745`

### 🟡 low — `esc()` doesn't escape `"`, so a job URL can break the digest

## site-watch

### 🟠 medium — Public endpoint runs the full check and can send Telegram messages
`src/index.js:117` · commit `65eefd8` (introduced in `56da863`)
Every request that isn't a valid `POST /beat/...` falls through to `run(env)`. That includes any path, any method, and a beat request with the wrong key. Anyone who finds the workers.dev URL can trigger probes with 5 s retries, KV writes and Telegram alerts. Concurrent runs also race with the cron on the `up:*` state and can send duplicate alerts. Fix: make the manual check read-only, returning the last state from KV without probing or writing, or require the `x-beat-key` header for it. Return 404 for anything that isn't the manual-check route.

### 🟠 medium — Alert state is saved before the Telegram send, and the message isn't HTML-escaped
`src/index.js:93-99, 66-67, 24` · commits `56da863`, `65eefd8`
The site state (`up:*`) and the `alerted:*` flag are written before `telegram()` runs. `telegram()` only logs failures. `parse_mode: 'HTML'` is also used with `r.why`, which comes from `e.message` and can contain `<` or `&`. If Telegram rejects the message (400 on bad HTML, 429, or a network error), the alert is lost for good. The state says it was already reported, so nothing retries it. Fix: escape dynamic text, and have `telegram()` return success or throw. Write the KV state only after a successful send.

### 🟡 low — Heartbeat alerts fire immediately after deploy
`src/index.js:63-68` · commit `65eefd8`
On the first cron run after deploy there is no `beat:*` key. Once the Prague hour is past the deadline, `devlog` (10:00) and `digest` (14:00) alert as "zatím nikdy". `job-mail` alerts at once, since it has no last beat. This is a false alarm on rollout, and it repeats whenever the KV namespace is reset. Fix: when there is no `beat:*` key, write "now" as the baseline and skip the alert, the same way the site check skips its first run.
