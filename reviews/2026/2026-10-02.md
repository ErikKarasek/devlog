### 🟠 medium — Round-robin loop terminates too early when all medium findings fit in fewer than 20 rounds

`src/review-tasks.js:78` · commit `33ad0b3`

The outer loop guards `turns.length < serious.length`, but `serious` includes **high**-severity items too, not just mediums. If there are, say, 3 highs and 2 mediums, the guard sees `serious.length === 5`; the inner loop can only ever add those 2 mediums, so `turns.length` tops out at 2 and the loop happily runs all 20 iterations for no reason — a minor waste — but the real breakage is the opposite case: when there are *more* mediums than highs, the early-exit condition (`turns.length < serious.length`) is satisfied before all medium items have been interleaved, silently dropping some findings. The cap should compare against the medium count, not the full serious count. Fix: change the guard to `turns.length < [...byRepo.values()].reduce((s, l) => s + l.length, 0)` (or compute a `mediumCount` variable beforehand and use that).

### 🟡 low — `latestReview()` can return `undefined` and crash with an unreadable error

`src/review-tasks.js:62` · commit `33ad0b3`

If the `reviews/` directory is empty or contains no `.md` files, `files.sort().at(-1)` returns `undefined`; the `.match(...)` call on line 62 then throws `TypeError: Cannot read properties of undefined`, and `readFileSync` on line 63 would also fail — but neither error gives any indication of *why*. This silently breaks the entire script whenever the review file is missing (e.g. the first run after a fresh clone, or if `review.js` didn't produce output). Fix: add an explicit check after `latestReview()` — `if (!file) { console.error('No review file found'); process.exit(1); }` — so the failure message is actionable.

## dispecink

### 🟠 medium — Guard resumes (and re-invokes) any agent you manually un-paused during a limit window

`src/main.ts:208-212` · commit `228e9e7`

`guardClaude` stores paused-agent IDs in `localStorage` and, when usage drops, filters the full non-terminated agent list against that key — **regardless of whether the agent's current status is still `"paused"`**. If you manually resume an agent while the limit is active (e.g., to let it finish one urgent task), `back` still includes it when usage recovers, so `agentResume` + `agentInvoke` are both fired at it again, potentially starting a duplicate run.

Fix: filter `back` to only agents whose status is currently `"paused"` — `agents.filter(a => paused.includes(a.id) && a.status === "paused")` — so manually-resumed agents are simply removed from the tracked list on the next successful wake.

### 🟡 low — Morning digest is silently skipped for the whole day when Paperclip API is unreachable at 8 am

`src/main.ts:251` · commit `228e9e7`

`localStorage.setItem(DIGEST_KEY, today)` is written **before** the early-return check on line 252. If every `paperclip_request` call fails (Paperclip temporarily offline, network hiccup), `done`, `stuck`, and `working` are all empty, the function returns without sending anything — but today's date is already committed, so none of the ten-minute retries will attempt it again.

Fix: move `localStorage.setItem(DIGEST_KEY, today)` to just before the `invoke("telegram_send", …)` call, so the dedup key is only written after there is actually something to send (or accept that an empty digest also deserves the guard, and add a comment explaining that choice).

## spidey-portfolio

### 🟡 low — Portrait images use hardcoded landscape intrinsic dimensions, causing layout shift
`src/case-study/CaseStudy.tsx:101` · commit `49044c8`

The `<img>` element always renders with `width={1600} height={1029}` (a ~1.55:1 landscape ratio), but the phone screenshots marked `portrait: true` (`wisp-phone.webp`, `wisp-agents.webp`) are taller than they are wide — so the browser reserves a landscape-shaped box, then jumps to the correct portrait height once the image bytes arrive, producing a visible layout shift (CLS). Fix: pass the intrinsic dimensions through the shot object (e.g. `width?: number; height?: number`) and fall back to `1600`/`1029` only for landscape shots, or drop the explicit `width`/`height` attributes on portrait shots entirely and let the browser infer them.
